# W0.1 acceptance criteria

**HAR-01** `uv sync` builds the project; `course-assistant --version` prints the version; the wheel ships only `src/course_assistant`; `.gitattributes` forces LF; MIT licence present.
**HAR-02** CI runs ruff, pyright, pytest, the build, the secret scan, the corpus guard and every gate self-test on push and pull request, on Python 3.11, 3.12 and 3.13 on ubuntu-latest and macos-latest, with read-only permissions and no secrets.
**HAR-03** `verify_graph_eligibility.py` fails on cycles, unknown dependencies, and any node building or green ahead of a dependency; an external node is recognised by `owner attest` in Verified by; the live graph is eligible and has 31 nodes.
**HAR-04** `node_start.py` refuses to start a node whose dependencies are not green, whose spec files are missing, or whose criteria miss a capability; check-only mode writes nothing.
**HAR-05** `node_converge.py` runs the 12 gates in the documented order (evalreg at 8, safety at 9, app-smoke at 10), reports every gate after a failure, and its self-test shows each gate failing on a planted defect; external-node rows pass only with `attest=OWNER D-n`, and code-node rows never accept `attest=`.
**HAR-06** `graph.md` and `catalog.tsv` match the Tech Spec node and capability tables exactly; `decisions.md` holds D-1 to D-22; `lessons.md` holds L-1 to L-18 or later; `changelog.md` has a [W0.1] entry; `status.py` prints the graph and a node; the catalog round-trips byte for byte.
**HAR-07** The secret scan detects every key format it lists, honours the allow marker, and the live repo is clean.
**HAR-08** Under the D-23 threat model, the corpus guard fails, without printing a private term or a path that holds one, on: (a) a course-type file (documents, archives, transcripts, recordings, by suffix or by content magic) outside `sample_course/` (case-sensitive), anything in a `corpus/` folder at any depth, held-out data other than `golden/heldout/MANIFEST.json`, a tracked `.private-terms`, a symlink leaving the repo; (b) a private term in any file's text or name written in any of these forms: plain; any case; split across lines (including behind `#` or `>`), by tags, emphasis, hyphenated line breaks, or HTML/Markdown links (inline or reference); inside URLs and attributes; with entities, %-encoding, JSON escapes (`\uXXXX`, `\n`), quoted-printable, zero-width or other invisible characters, fullwidth forms; with accents removed or transliterated (ø, æ, ł, ß, umlauts written out); as a slug or camelCase word (terms of 8+ letters); in UTF-8 text; and (c) every file is either UTF-8 text without NUL bytes or an allowed binary: a file in `sample_course/` or `docs/assets/` whose suffix is in the guard's suffix table and whose content magic matches that suffix; anything else (cp1252, UTF-16 or UTF-32 text with or without a BOM, a binary elsewhere, a binary with an unknown suffix or mismatched magic) is a finding (D-26, D-27); inside zip, gzip, bz2 or xz archives one level deep, Office and OpenDocument files, and PDF Flate text streams; in a symlink's target text; and on an unreadable file (reported as unreadable). It does not flag ordinary prose: a short term never matches inside a longer word, and a phrase never matches across a comma, semicolon, colon, `!` or `?`, or a sentence-ending full stop (one followed by a space or line end), that the term does not itself contain; a full stop inside an identifier (an email, domain or file name) is part of a slug. Double %-encoding is decoded. Every case above is in the guard's self-test. `.private-terms`, `corpus/` and `golden/heldout/*` are git-ignored, and the guard runs in the pre-commit hook, where the private terms exist (D-25).
