# R3.1 acceptance criteria

OSS-01 to OSS-07 and OSS-09 are proved offline (tmp folders, monkeypatched environment, the
workflow and README files parsed as data, an offline `uv build`). OSS-08 is the publish, the
tag and the published-package check, proved only by owner attest (`OWNER D-n`, D-60).

**OSS-01** Distribution `course-assistant`, CLI `course-assistant`; release workflow with trusted publishing on a tag. `pyproject.toml` names the distribution and the script; `.github/workflows/release.yml` triggers only on `v*.*.*` tag pushes, builds the sdist and wheel and runs the exclusion test (`tests/harness/test_packaging.py`) and the tag/version and artefact checks before upload; the publish job needs the build, runs in the `pypi` environment with `id-token: write` as its only permission, runs only when the tagged commit is on `main`, and passes no password or token to `pypa/gh-action-pypi-publish`; every action is pinned to a 40-hex SHA and every checkout sets `persist-credentials: false`; no PyPI token appears anywhere in the repo.
**OSS-02** `course-assistant init` writes `config.yaml`, `manifest.yaml`, `assessments.yaml` and `.env.example` from packaged templates into the target folder; existing files are kept byte-for-byte and reported, the rest written; the written config and manifest load with the project's loaders; `.env.example` holds names with empty values; exit 0, or 2 when the target cannot be used; no network.
**OSS-03** `course-assistant doctor` reports fixed-message lines for python, extras, config, secrets, vector_store and corpus; a missing or blank `OPENAI_API_KEY` is a FAIL that names the variable and never prints any value (a sentinel key value never appears in stdout or stderr); a malformed or placeholder vector store id fails the format check; a missing manifest file fails corpus; exit 0 with no FAIL, 1 with any FAIL, 2 on bad arguments; no network (socket connect refused in the test).
**OSS-04** Docs: quickstart on the sample course (first grounded answer in under 10 minutes with your own key), bring your own course (`init`, `doctor`, `ingest --dry-run`), writing a golden set and evaluating it, cost and privacy; every command in them exists in the CLI or Makefile.
**OSS-05** `CONTRIBUTING.md`, `SECURITY.md` and `CODE_OF_CONDUCT.md` exist; `.github/ISSUE_TEMPLATE/` holds a bug and a feature form and a `config.yml` that disables blank issues and links security reports to `SECURITY.md`; `.github/pull_request_template.md` exists and points security reports to `SECURITY.md`; the bug form warns against pasting keys, passcodes or learner text.
**OSS-06** `PRIVACY.md` states no telemetry and that learner and course data go only to the OpenAI project the operator configures; no telemetry dependency or call in the package.
**OSS-07** An example GitHub Action runs the course-ta gate and fails the job when a threshold fails; its actions are SHA-pinned.
**OSS-08** Tag v0.1.0, semver policy, and a clean-venv install of the published package runs `--version`, `doctor` and the sample-course replay (owner attest). The owner registers the trusted publisher, protects the `pypi` environment, tags `v0.1.0` on main, approves the publish, runs the clean-venv check and records `OWNER D-n` opening "Attests R3.1". Until then the row stays not green and R3.1 cannot flip green.
**OSS-09** README with screenshots of both pages, a step-by-step guide and every important link (PyPI, docs, live demo, EvalKit, sample-course licence, issue tracker, security policy); every image and link is absolute (raw GitHub URLs for images and SVGs, `github.com/.../blob|tree/main/` for files), so it renders on PyPI; only `#` anchors are relative.
