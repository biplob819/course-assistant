# B2.5 acceptance criteria

All criteria are proved offline: scripted model outputs through N1.2's `respond`, D3.1's real passkey gate and guard (file-backed spend counter), a file-backed app store, an in-memory trace sink, the packaged golden replay fixture, and Streamlit's `AppTest` for the page; no network.

**CHT-01** Session picker ("All sessions" default) and a "New conversation" button. `session_options` lists "All sessions" first and one label per live-corpus session; "All sessions" is the default and asks with no session filter, a picked session reaches `Assistant.turn` as the filter; changing the scope starts a new conversation; "New conversation" closes the open one so the next turn has an empty window; the page draws the picker and the button.
**CHT-02** Answer card with source chips that open the unit text; AI label and "check the cited slide" note. An answered card carries one chip per citation holding the cited unit's exact corpus text, the AI label and the check note; a citation missing from the corpus says so; every golden replay answer renders the card its status calls for; on the page each chip is an expander holding the unit text.
**CHT-03** Not-covered reply with "Ask the teaching team" button. Only a not-covered reply showing `NOT_COVERED` offers the button (off-topic and injection do not); the button queues the turn through B2.1 with the kept draft, a second tap returns the first escalation, and a handed-over turn is queued without a tap.
**CHT-04** Notice at first use, history, delete. B2.2's notice is shown until the learner accepts the current version, asking is refused before then and after withdrawal, `improve_course` is a separate optional purpose; history shows only this learner's turns with teaching-team replies labelled; delete removes one conversation or everything (app rows and trace lines) and starts a fresh conversation.
**CHT-05** Accessibility: keyboard, labels, status not shown by colour alone. Every status has its own text label and text icon; the page uses only Streamlit widgets with visible labels (no `unsafe_allow_html`, no hidden labels, no custom HTML or script); learner and answer text are Markdown-escaped.
**CHT-06** Bring your own OpenAI key: a visitor may enter their own key, which is used for that session only, never stored or logged, and never replaces the passkey check. The key field is reachable only after the passkey; the key is held in an `OwnKey` (no repr, no pickle, no copy), used only to build that request's responder, absent from every log record, trace record, store row, file under the app folder, widget state and repr, and cleared on sign-out; with a key but no passkey, no method answers, reads history or stores anything.
